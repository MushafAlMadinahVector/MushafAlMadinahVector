# Repository Audit & Modernization Assessment — 2026-10-26
## Mushaf Al-Madinah Vector Edition (`Al-Madinah`)

---

### 1. What already exists

1. **Repository & Upstream Relationship**:
   - Local Git repository configured with `origin` (`kausikhussain/Al-Madinah`) and `upstream` (`MushafAlMadinahVector/MushafAlMadinahVector`).
   - Upstream commit `a6f52f8b05fa28cdffb637cbbab0ed30515bbeb2` contains the complete 604-page Mushaf Al-Madinah collection named in the strict pattern `001___Hafs39__DM.ai` through `604___Hafs39__DM.ai`.
2. **Authoritative Source Artwork (`quran-pages/`)**:
   - Initial checkout lacked local blobs (partial clone). Representative authentic source files (`001`, `002`, `003`, `004`, `005`, `006`, `007`, and `604___Hafs39__DM.ai`) have been restored byte-for-byte from upstream without modification.
   - Binary inspection revealed that the `.ai` files are structured as standard Adobe Illustrator `%PDF-1.5%` documents with embedded vector streams, font glyph outlines, decorative borders, and diacritical marks.
3. **Usage Rights & Licensing (`LICENSE`)**:
   - Preserves the bilingual intellectual property declaration of the King Fahd Glorious Quran Printing Complex (KFGQPC), Al-Madinah Al-Munawwarah.
   - Direct links to official source (`https://dm.qurancomplex.gov.sa/`) and official usage rights (`https://dm.qurancomplex.gov.sa/rights/`).
4. **Tooling & Scripts (`scripts/`)**:
   - `scripts/convert-previews.py` & `scripts/convert-previews.mjs`: Multi-engine vector conversion pipeline supporting PyMuPDF (`fitz`) and Inkscape CLI.
   - `scripts/generate-manifest.mjs`: Inventories source files, computes SHA-256 cryptographic hashes, file sizes, and records display status.
   - `scripts/verify-manifest.mjs`: Integrity validator checking page numbers, duplicates, and referenced SVG display outputs.
5. **Frontend Application**:
   - `index.html`, `app.js`, `styles.css`: Static bilingual (English/Arabic) web application.

---

### 2. What works

- **Asset-Safe Build & Verification**: `npm run build` and `npm run verify:assets` pass completely.
- **High-Fidelity Vector Conversion**: The PyMuPDF pipeline accurately converts the embedded `%PDF-1.5%` vector streams of the `.ai` files into pure, scalable vector SVGs in `public/previews/` with zero glyph clipping or distortion.
- **Traceable Manifest Generation**: `npm run manifest` computes exact SHA-256 hashes and maps source filenames to preview assets.
- **Static Web Server**: `npm run serve` runs cleanly on `http://localhost:3000` with instant response times (`HTTP 200 OK`).
- **Interactive Browsing & Navigation**: Page selection, zoom controls (+, -, reset, fit width/page), search filtering, and Arabic/English language direction toggling function reliably.

---

### 3. What is missing

- **Full Local 604-Page Offline Bundle**: Upstream contains all 604 pages (~600 MB of vector `.ai` data). Currently, representative pages are converted locally while the remainder can be fetched or generated as needed.
- **Quranic Structural Metadata**: The viewer lacked Surah and Juz indexing for the 604 pages, making contextual navigation dependent on bare numbers.
- **Advanced Viewer Controls**: Missing drag-to-pan when zoomed in, full-screen viewing mode, keyboard shortcuts (`f`, arrows, etc.), and double-click to zoom.
- **High-End Bespoke Typography & Editorial Design**: The UI used basic system styling rather than a world-class, museum-grade editorial design with warm ivory tones, dark Quranic green contrast, and refined Arabic typography.

---

### 4. What can be improved safely

- **Bespoke Editorial Interface**: Elevate the design with a warm ivory/parchment background (`#FAF7F0`), deep midnight green (`#12221B`), subtle antique brass/gold accents (`#B39356`), and classic typography (Cinzel/Cormorant Garamond + Inter + Amiri/Noto Naskh Arabic).
- **Interactive Pan & Drag**: Allow smooth mouse drag / touch panning on the preview stage when zoomed in.
- **Surah & Juz Mapping**: Equip the interface with authentic Quranic metadata (114 Surahs, 30 Juz, page ranges) for context without altering any source artwork.
- **Full-Screen Reading**: Provide an unobstructed, distraction-free view for in-depth inspection of calligraphy.
- **Technical Integrity Inspector**: Add an on-demand modal or sidebar showing SHA-256 checksums, byte counts, and source file metadata for transparent verification.

---

### 5. What must remain unchanged

- **Zero Quranic Modification**: No `.ai` source file may ever be modified, renamed, reconstructed, or replaced.
- **No AI Calligraphy or OCR Replacement**: Quranic text must never be generated by neural models or substituted with OCR text.
- **Preserve Source File Distinction**: Original files in `quran-pages/` must remain strictly isolated from generated previews in `public/previews/`.
- **KFGQPC Ownership & License Notice**: The `LICENSE` file and official KFGQPC usage terms must be preserved intact.
- **Upstream Provenance**: Maintain attribution to the upstream repository (`MushafAlMadinahVector/MushafAlMadinahVector`) and the King Fahd Complex.

---

### 6. Legal & technical details needing ongoing verification

1. **Usage Rights**: Official terms permit free non-commercial and commercial digital use in web, apps, printing, and publishing, but restrict commercial physical printing of physical copies in Saudi Arabia.
2. **Code vs. Artwork Licensing**: New frontend and tooling code should carry a clear permissive license (e.g. MIT) for the software alone, while explicitly declaring that all Quranic calligraphy remains the intellectual property of KFGQPC.
3. **Distribution of Derivative SVGs**: Maintaining generated SVG previews in Git vs. generating on-demand or via release bundles should be decided by repository maintainers to avoid unnecessary repo bloat.
